# ARCHITECTURE.md

## Overview

AI Support Toolkit is a server-rendered Flask application for infrastructure
troubleshooting. A user selects a support domain, submits logs or an issue
description, and receives a structured response generated by OpenAI. Submitted
sessions are stored in a local SQLite database and can be searched, reviewed,
and counted by support mode.

This document describes the implementation currently present in the
repository. It is a draft, not a target-state design.

## System Context

```text
Browser
  |
  | HTTP form requests and rendered HTML
  v
Flask application (app.py)
  |                 |
  |                 +--> Jinja templates + static/style.css
  |
  +--> Prompt builders (prompts/)
  |       |
  |       v
  +--> OpenAI service (services/openai_service.py)
  |       |
  |       v
  |    OpenAI API
  |
  +--> Database functions (database/db.py)
          |
          v
       SQLite support_history.db
```

## Components

### Web Application

`app.py` creates the Flask application, loads environment variables, initializes
the database at import time, and defines all routes.

| Route | Methods | Responsibility |
| --- | --- | --- |
| `/` | GET, POST | Submit issues, select prompts, display responses, search history, and paginate recent sessions |
| `/session/<int:session_id>` | GET | Display one stored session or the missing-session page |
| `/session-search` | POST | Redirect a numeric session lookup to its detail URL |
| `/stats` | GET | Display total and per-mode session counts |

The `/` POST handler distinguishes forms by checking whether `filter_mode` is
present. Analysis submissions build a prompt, call OpenAI, save the returned
HTML, and render the refreshed history.

### Prompt Layer

The `prompts/` package contains one builder per support mode:

- Azure
- AWS
- Terraform
- Remote Access & VDI
- General Infrastructure

Each builder combines user text, a domain-specific engineer role and focus
areas, and shared rules from `prompts/common_prompt_parts.py`. The requested
answer shape includes likely issue, severity, troubleshooting steps,
recommended commands, and additional notes.

Prompt selection currently uses an `if`/`elif` chain in `app.py`. Any value not
matching the first four explicit modes falls back to the general prompt.

### OpenAI Service

`services/openai_service.py`:

1. Loads environment variables.
2. Creates a module-level `OpenAI` client using `OPENAI_API_KEY`.
3. Sends a single user message through the Chat Completions API.
4. Uses the fixed model `gpt-4.1-mini`.
5. Converts returned Markdown to HTML with fenced-code support.
6. Converts authentication, timeout, and generic exceptions into HTML error
   boxes.

The route receives both successful output and service errors as HTML strings.
It does not currently distinguish them before saving a session.

### Persistence

`database/db.py` uses Python's built-in `sqlite3` module. Every operation opens
and closes its own connection to the relative filename `support_history.db`.

The table is created automatically if absent:

```sql
CREATE TABLE support_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp TEXT,
    support_mode TEXT,
    prompt TEXT,
    response TEXT
);

CREATE TABLE session_attachments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id INTEGER NOT NULL,
    filename TEXT NOT NULL,
    mime_type TEXT NOT NULL,
    file_size INTEGER NOT NULL,
    file_data BLOB NOT NULL
);
```

Stored fields:

- `id`: sequential session identifier.
- `timestamp`: local server time formatted as `YYYY-MM-DD HH:MM:SS`.
- `support_mode`: UI label for the selected domain.
- `prompt`: the user's original issue text, despite the column/function
  parameter name `prompt`.
- `response`: rendered HTML returned by the OpenAI service.

Validated original uploads are stored in `session_attachments` and associated
with the saved session. Extracted prompt text remains transient.

### Presentation

Jinja templates render four pages:

- `templates/index.html`: analysis form, response, search, history, pagination.
- `templates/session.html`: stored prompt and response with navigation.
- `templates/stats.html`: aggregate session cards.
- `templates/session_not_found.html`: missing-session fallback.

`static/style.css` provides a shared dark theme. There is no client-side
application framework. The only JavaScript disables and relabels the Analyze
button during submission.

## Main Request Flows

### Analyze an Issue

1. The browser posts `support_mode` and `log_text` to `/`.
2. Flask rejects blank issue text with an inline error.
3. Flask chooses the domain prompt builder.
4. The prompt builder combines issue text with shared and domain rules.
5. The OpenAI service requests a completion.
6. Markdown output is converted to HTML.
7. Flask stores mode, original issue text, and HTML response in SQLite.
8. Flask stores accepted original uploads as session attachments.
9. The page renders the response and refreshed recent-session list.

### Search History

1. The browser posts `filter_mode` and `search_text` to `/`.
2. The database query applies an exact mode filter and/or a prompt `LIKE`
   search.
3. All matching rows are returned in descending ID order.
4. Results render in the same recent-session list; filtered results are not
   paginated.

### View a Session

1. The browser requests `/session/<id>`.
2. SQLite returns the full row for that ID.
3. The template renders the original issue and stored HTML response.
4. Missing IDs render `session_not_found.html`.

### View Statistics

1. The browser requests `/stats`.
2. Flask executes one total-count query and one query for each of five modes.
3. The template renders six statistic cards.

## Trust Boundaries and Security Notes

- User issue text crosses from the browser into Flask, prompt construction,
  OpenAI, and SQLite.
- Infrastructure logs may contain secrets, hostnames, addresses, identifiers,
  or other sensitive operational data.
- OpenAI output is converted to HTML and rendered with Jinja's `safe` filter.
  The same is true when responses are read back from SQLite.
- Generic exception text is embedded in an HTML response.
- There is no authentication, authorization, CSRF protection, rate limiting,
  input-size limit, retention control, or data redaction in application code.
- `.env` contains the API credential name and must remain private.

These notes describe current boundaries and risks; they do not assert that the
application is suitable for untrusted or internet-facing use.

## Deployment and Operations

Local development can use `python app.py`, which launches Flask's development
server with `debug=True`. The Docker image uses one Gunicorn worker with four
threads, listens on port `8000`, and runs as a non-root user. A `/data` volume
persists `support_history.db` without changing the application's relative
database path.

The repository does not currently define:

- A hosted cloud platform or reverse proxy.
- Database migrations or backups.
- Structured logging or external monitoring.
- Automated tests or CI.

## Architectural Constraints

- The relative SQLite path makes behavior dependent on the process working
  directory.
- Module-level app, database initialization, and OpenAI client creation make
  isolated testing harder.
- Stored responses are presentation-ready HTML, coupling persistence to current
  rendering decisions.
- Support-mode labels are duplicated across Python and HTML.
- Route, orchestration, validation, and response handling are concentrated in
  `app.py`.
- SQLite is reasonable for a local, low-concurrency tool but may not fit a
  multi-user deployment without revisiting persistence requirements.

## Assumptions

- The intended current use is a local, single-process development tool.
- The existing SQLite file should be preserved as local user data.
- Timestamps use the host machine's local time; no timezone contract exists.
- Session IDs may have gaps even though current navigation assumes adjacency.
- Authentication and shared-user tenancy have not yet been designed.
